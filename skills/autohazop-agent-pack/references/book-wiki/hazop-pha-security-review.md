## Core use

Use for HAZOP/PHA method selection, node definition, design intent, guidewords, deviation phrasing, causes, consequences, safeguards, recommendations, and security vulnerability review routing.

## Quality gates

Check that every worksheet row has a specific deviation, credible cause, process-linked consequence, existing safeguard, action owner, and no hidden LOPA/IPL credit.

## AutoHAZOP use

Use graph evidence to prove tag existence, direction/path logic, safeguard location, and cross-node consequence propagation before accepting an LLM-generated row.

## Answer Pattern

When using this wiki, answer with:

- `Decision`: the best current engineering decision or review status.
- `Basis`: source slug(s), page count/source note, and assumptions.
- `Missing data`: project criteria, tags, drawings, calculations, inspection/proof-test evidence, or data tables needed.
- `Cautions`: dependency, uncertainty, applicability, or OCR/manual-lookup limitations.
- `Next action`: specific review, calculation, field check, or documentation update.
